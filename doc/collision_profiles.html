System Shock VR — Resolved Collision Profiles

Computed by applying DefaultEngine.ini over BaseEngine.ini for the [/Script/Engine.CollisionProfile] section.

How the merge resolves

  • UE loads BaseEngine.ini first, then DefaultEngine.ini applies on top.
  • The project's DefaultEngine.ini issues paired -Profiles=(Name=X,...) / +Profiles=(Name=X,...) for every built-in profile, so BaseEngine's contribution is fully overwritten.
  • +EditProfiles then patches individual CustomResponses entries on top, keyed by channel name (same name overrides, new names append).
  • Unspecified channels fall back to each channel's DefaultResponse.
  • +Profiles entries with (Channel="X") and no Response= default to ECR_Block per FResponseChannel constructor — that's why RangedWeapons ends up Block in many profiles despite its channel default being Ignore.

Notes

  • +EditProfiles is a merge, not a replace. Channels you don't list keep whatever the +Profiles line gave them. E.g. PhysicsActor first sets WorldDynamic=Overlap, then +EditProfiles overrides it back to Block (line 53).
  • Empty Response= means Block. An entry like (Channel="RangedWeapons") with no Response= is parsed as ECR_Block, which is how a Trace-channel with a default of Ignore can end up Block on many profiles.
  • Redirects are name-only. ProfileRedirects (PhysicsActor → PickupPhysicsActor → PickupPhysicsBody) and CollisionChannelRedirects (Player → Pawns → RangedWeapons) only retarget stale names in saved assets — they do not affect the runtime profile set.
  • BaseEngine's +OldProfiles is legacy-only — those names exist solely so that ProfileRedirects can remap them onto current profiles.
